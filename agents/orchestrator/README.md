# Orchestrator — reference

Port **8000** · Owner: M1 (lead) · Status: **complete**, pending live runs against real specialists.

This is the only service the browser talks to, and the only agent that calls
the others. It also serves the web UI from `ui/web/` at `/`. If you are
building a specialist, you never need to edit anything here; read section 3
to see exactly what it sends you.

---

## 1. Endpoints

| Method | Path | Called by | Purpose |
| --- | --- | --- | --- |
| POST | /chat | UI | `{conversation_id, message}` → `{reply, status, sources, extra, trace}` |
| POST | /auth/login | UI | Proxied to Account Agent `/auth/login`. Passes its status and body through. |
| POST | /auth/verify-otp | UI | Proxied. On 200 with `token`, stores it in the session and returns `{logged_in: true}`. The browser never receives the token. |
| POST | /auth/logout | UI | Clears the session token |
| GET | /auth/status | UI | `{logged_in}` for the server-issued cookie session |
| GET | /agents/health | UI | Polls the three specialists' `/health` so the browser never contacts them directly |
| GET | /tickets | UI (console) | Proxied to Supervisor `GET /tickets` |
| GET | /health | run_all.py | |
| GET | / | browser | the single-page UI |

Rate limits on `/chat`: 20/min per server-issued session cookie, 60/min per IP. The 21st
request gets 429 with a polite message.

## 2. The decision loop (`router.py`)

Every step can end the turn. That is what makes this an agent and not a pipe.

| # | Step | Ends the turn when | Audit decision |
| --- | --- | --- | --- |
| 1 | Rate limit (`main.py`) | over limit → 429 | `rate_limited` |
| 2 | Sanitise (`shared.security.sanitize`) | empty → ask to clarify | — |
| 3 | Injection check (`is_injection`) | matched → refuse | `injection_blocked` |
| 4 | NLU (`nlu.py`) | — | `intent=<x>` with confidence and method |
| 5 | Assess (Supervisor `task=assess`) | `escalate` true **or** intent is `complaint` → Supervisor `task=escalate` → ticket | `assess`, `escalate` |
| 5b | Clarify | confidence < 0.5 or `needs_clarification` → one question | `clarify` |
| 6 | Auth gate | intent in `AUTH_REQUIRED` and no token → `needs_auth` | `auth_required` |
| 7 | Route | `out_of_scope` → polite refusal, else envelope to `INTENT_OWNER[intent]` | `answered_locally` / `route-><agent>` |
| 8 | Handle result | `ok` / `needs_auth` / `forbidden` / `not_found` / `escalate` / `error` | `result=<status>` |
| 9 | Compose (`composer.py`) | AI disclosure on first turn, sources, cards, trace | `ai_disclosure_shown` |

### NLU (`nlu.py`)

One LLM call via `shared.llm.generate` with a JSON schema → `{intent,
confidence, entities, needs_clarification}` validated by Pydantic. Bad JSON is
retried once, then the keyword classifier answers. Regex phone and amount
entities are always merged in; spaCy `DATE` and `GPE` are added when the model
is installed. `method` in the trace tells you which path answered.

### Sessions (`session.py`)

In memory, keyed by `conversation_id`: token, last 10 turns, consecutive
failure count, disclosure flag. The failure count is passed to the Supervisor
as `failed_count`.

## 3. What the Orchestrator sends each specialist

All calls: `POST http://127.0.0.1:<port>/handle`, header `X-Internal-Key`,
body is an `Envelope`, 20 s timeout, one retry. Network failure becomes an
`error` reply; the user is apologised to and offered a human.

| To | intent | payload | auth_token |
| --- | --- | --- | --- |
| knowledge_agent | the 6 knowledge intents | `{query, entities}` | `null` |
| account_agent | bill_enquiry, quota_check | `{query, entities}` | the session token |
| supervisor_agent | the current intent | `{task:"assess", message, intent, failed_count}` | `null` |
| supervisor_agent | complaint | `{task:"escalate", history:[{role,text}], reason, priority}` | `null` |

`entities` shape: `{phone:[], amount:[], date:[], country, package_name, data_amount}`.

---

## 4. What the Orchestrator does with each reply status

| status | User sees | Session |
| --- | --- | --- |
| ok | `answer`, `sources` as cards, any extra keys as cards (`bill_diff`, `quota`, `ticket_id`) | failures reset to 0 |
| needs_auth | login gate | — |
| not_found | honest message + "Talk to a human" | failures + 1 |
| escalate | `answer`, ticket card | — |
| error | apology + "Talk to a human" | failures + 1 |

## 6. Known limitations (stated in the README on purpose)

In-memory sessions; conversation id generated by the browser; phrase-list
injection filter; per-conversation rate limit resets with a new id; plain HTTP
between agents on localhost.
